# AGENTS.md — React 项目 Agent 开发规则

## 1. 项目技术栈

- Vite
- React
- TypeScript
- Ant Design
- Tailwind CSS
- Zustand
- Axios
- React Router v6

不得擅自替换技术栈、升级主版本或新增同类依赖。

开发前检查现有适配层的导出与调用方式。

## 3. 依赖隔离（强制）

业务代码只能依赖项目内部 API，不得直接依赖第三方库的实现。

| 第三方库 | 允许直接导入的位置 |
|---|---|
| `antd` | `src/adapters/ui/**` |
| `axios` | `src/adapters/http/**` |
| `zustand` | `src/adapters/store/**` |
| `react-router-dom` | `src/adapters/router/**`、`src/router/**`（仅路由配置/适配所需） |
| `tailwindcss` | 构建配置、全局样式 |

React、React DOM 和 TypeScript 是基础框架依赖，可正常使用。

业务页面、业务组件、业务 Hooks、业务 Services、业务 Stores 禁止直接导入上表中的第三方库。必须通过 `@/adapters/...` 的项目统一入口使用。

## 4. 适配层规则

- 每个适配层必须有 `index.ts` 统一导出。
- 对外暴露项目需要的稳定 API，不要机械复制第三方库全部 API。
- 适配层内部可以依赖对应第三方库；业务层不能依赖其内部实现。
- 修改适配层公共 API 前，先搜索所有调用方并评估兼容性。
- 优先保持向后兼容；确需破坏兼容时，必须同步迁移所有调用方并记录变更。
- 不允许在业务层通过 `as any`、深层导入或其他方式绕过适配层。

## 5. 分层职责

- `adapters/`：第三方库适配与项目技术接口。
- `core/`：配置、常量、通用类型、无业务含义的工具。
- `components/`：跨业务复用的项目组件。
- `modules/`：业务页面及模块内组件、Hooks、类型。
- `services/`：业务 API 定义，只调用统一 HTTP 适配层。
- `stores/`：业务状态定义，只使用统一 Store 适配层。
- `router/`：业务路由表、路由装配与权限配置。
- `styles/`：全局样式、主题变量和 Tailwind 入口。

不得将业务规则放入 `adapters/`，也不得让适配层依赖具体业务模块。

## 6. 编码要求

- 使用函数组件和 React Hooks。
- 使用 TypeScript，禁止新增 `any`；不确定类型时优先使用 `unknown` 并进行收窄。
- 公共组件、公共函数、适配层 API 必须声明明确类型。
- 组件只负责展示和交互；复杂业务逻辑抽到模块 Hooks 或 Services。
- API 请求放在 `services/`，不得散落在页面组件中。
- Store 按业务域拆分，禁止建立承载所有业务状态的巨型 Store。
- 异步操作必须处理加载、成功和失败状态；页面需按场景处理空数据。
- 不得吞掉异常；需要转换错误时保留足够的错误上下文。
- 不得为了完成单个需求引入重复依赖或重复实现。
- 禁止无关重构、无关格式化和擅自修改公共 API。

## 7. UI 与样式

- 复杂交互组件使用项目封装的 UI 组件。
- 页面布局、间距、尺寸优先使用 Tailwind CSS。
- Ant Design 主题和全局样式集中管理。
- 不得在业务页面随意覆盖 Ant Design 内部 DOM 类名。
- 高频复用样式优先抽成公共组件或设计 Token。
- 不得同时用 Tailwind 和大量内联 `style` 重复表达同一套样式。

## 8. 新增依赖流程

只有现有技术栈无法合理满足需求时才考虑新增依赖。新增前必须说明：
1. 解决什么问题；
2. 为什么现有依赖无法满足；
3. 是否会增加适配层；
4. 依赖体积、维护状态和许可证风险；
5. 是否存在重复功能。

未经用户或项目负责人确认，不得新增依赖或升级依赖主版本。

## 9. 测试与交付

修改完成后，按项目已有脚本执行可用检查，至少尽可能执行：
- TypeScript 类型检查；
- ESLint；
- 相关单元测试；
- Vite 生产构建。

交付说明必须包含：
- 修改/新增文件；
- 实现内容；
- 新增或变更的项目内部 API；
- 是否新增依赖；
- 执行过的检查及结果；
- 未执行的检查和原因；
- 需要人工确认的风险。

不得声称执行了实际未运行的测试或构建。
