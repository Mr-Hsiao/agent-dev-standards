# 第三方库封装规范

## 目标
隔离依赖变化、统一配置和错误处理，不是为每个第三方函数增加无意义的转发层。

## 推荐封装边界
- 数据库：统一管理 Engine、Session 和 Base。
- Redis：统一管理连接池、序列化、超时和异常。
- HTTP：统一封装 httpx Client、超时、重试、鉴权和追踪 ID。
- 对象存储：统一封装上传、下载、删除和签名 URL。
- 消息队列：统一封装发布、消费、重试和死信处理。
- 邮件/短信/支付：用业务接口隔离具体供应商 SDK。

## 设计原则
- 业务层依赖稳定接口或应用服务，不直接依赖供应商 SDK 类型。
- 统一设置连接池、超时、重试和日志。
- 只对可安全重试的操作自动重试；写操作需具备幂等机制。
- 第三方异常转换为项目内部异常，保留原始异常作为内部 cause。
- 封装层提供健康检查与可观测性。
- 更换供应商时优先新增 Adapter，不修改业务流程。

## 避免
- 建立包含所有库函数的巨大 utils.py。
- 为抽象而复制第三方库完整 API。
- 让业务层接收或返回供应商 SDK 专有对象。
- 在每个业务模块重复创建 HTTP Client 或 Redis Client。
